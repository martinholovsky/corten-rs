Every language is read the way the Rust audit reads the same CWE: where Rust counts an analogue (panics and `Result` for the exception weaknesses, an `unsafe` init-array entry for a static code block), the other language's analogue counts too, so a difference in the table is a difference in the language, not in the reading.

## C beside Rust

Writable in C but not in Rust even with `unsafe` (4): [CWE-481](https://cwe.mitre.org/data/definitions/481.html) Assigning instead of Comparing, [CWE-483](https://cwe.mitre.org/data/definitions/483.html) Incorrect Block Delimitation, [CWE-484](https://cwe.mitre.org/data/definitions/484.html) Omitted Break Statement in Switch, [CWE-582](https://cwe.mitre.org/data/definitions/582.html) Array Declared Public, Final, and Static.

Writable in Rust with `unsafe` but not in C (2): [CWE-111](https://cwe.mitre.org/data/definitions/111.html) Direct Use of Unsafe JNI, [CWE-586](https://cwe.mitre.org/data/definitions/586.html) Explicit Call to Finalize().

## MITRE's language tags are not a measure

Each CWE lists the languages it applies to (`Applicable_Platforms`). Counting a CWE for a language when that list names the language, or a class it belongs to, gives the numbers below. They disagree with the per-CWE review in both directions: the tags record where a weakness has been documented, not what a language allows. Most of the over-count is hardware, physical and process weaknesses tagged *Not Language-Specific*.

| Language | Tags count it for | Audited writable | Tagged, not writable | Writable, not tagged |
| --- | ---: | ---: | ---: | ---: |
| C (C, Compiled, Memory-Unsafe, Not Language-Specific) | 838 | 789 | 90 | 41 |
| Rust (Compiled, Not Language-Specific, Rust) | 763 | 787 | 91 | 115 |

The Phase 0 ledger counted 853 for Rust from the same tags plus 46 judgement calls; the rule here is mechanical, so the two differ.
