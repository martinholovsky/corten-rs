# Changelog

Newest first. Releases are tags signed with the maintainer's OpenPGP key; verify one with `git verify-tag <tag>`.

## Unreleased

### Changed

- **`corten-sandbox` handles Landlock's newer filesystem rights** (2026-11-22; found while closing the UDP gap; owner asked for the fix). It handled only ABI v4's filesystem rights, so two later ones stayed allowed on every kernel that has them: driver `ioctl` commands on a device the program opens (`IoctlDev`, ABI v5, Linux 6.10) and connecting to a pathname UNIX socket created outside the sandbox (`ResolveUnix`, ABI v9, Linux 7.1). Both are now handled best effort, like the scopes and UDP, and granted on no path. Descriptors open before the sandbox keep their rights (Landlock decides at open), and a program's own `listen` socket stays reachable (`ResolveUnix` covers only servers created outside). New tests: `a_device_opened_in_the_sandbox_takes_no_driver_ioctl` (`stty -F /dev/null`: "Permission denied" instead of the driver's "Inappropriate ioctl for device") and `a_unix_socket_created_outside_cannot_be_connected_to`, each with an unconfined control and gated on the kernel. Evidence: Linux 6.17, Clippy clean, 19 of 19, hermetic smoke test 4 of 4; Linux 7.3.5 under QEMU, 19 of 19. Mutants caught: `IoctlDev` not handled (6.17), `ResolveUnix` not handled (7.3.5). GitHub's `ubuntu-24.04` image lists kernel 7.0 (its runner-images README, image 20261116.376.1), so CI runs the `ioctl` refusal and only the unrestricted branch of the UNIX-socket test.
- Owner decision recorded (2026-11-22, `docs/gates/phase-6.md`, the prebuilt-driver row): the driver's premise was corrected by measurement. `corten-driver` loads `librustc_driver` and `libLLVM` from the pinned nightly when it runs, so a prebuilt driver saves its build and the `rustc-dev` download, not the nightly. Chosen: the prebuilt, digest-pinned driver as decided, with `cargo corten` printing the exact `rustup` command for the pinned nightly (minimal profile) when it is missing, and no network call from the checker. Rejected: shipping the nightly's libraries with the driver (about 250 MB per platform, in the trusted base) and parking the driver. Not started.
- **CWE-306 holds for request handlers** (2026-11-22; the handler-level case `authz-proposal.md` deferred to batch 6, which the listener made testable). Four new variants in `corpus/CWE-306`, each rejected for its own reason: a handler that takes no `Authenticated` (E0593: `Listener::serve` accepts only `(&Authenticated, Request)`), a principal built from a request header (E0451), a socket bound with `std::os::unix::net::UnixListener` (the checker's ban) and a web framework as a dependency (the dependency policy). `good.rs` also serves a handler through a `listen` grant. The row stays E and verified; its mechanism now names the listener. Phase 6 corpus on macOS: 16 of 16 detected, 0 of 16 falsely rejected; making the header variant compile turned CWE-306 to "not detected" and failed the gate.
- **`corten-sandbox` filters UDP where the kernel has Landlock ABI v10** (Linux 7.2 and later; 2026-11-22; `landlock` 0.4.7 → 0.4.8, no new packages). The deferral in `docs/gates/phase-5.md` fired when `landlock` 0.4.8 shipped ABI v10's `BindUdp` and `ConnectSendUdp`. Owner decision: request them wherever the kernel has them, best effort like the v6 scopes, with ABI v4 still the floor. Unless `--allow-net` is given, every UDP bind and send is refused, except sends to port 53 when a `net` grant names a host (the system-resolver lookup, with `BindUdp` on port 0 for its ephemeral bind). Below ABI v10 nothing changes. Evidence: Linux 7.3.5 (Ubuntu's mainline build, SHA-256 checked, booted under QEMU): 16 of 16 sandbox tests, including the new `udp_with_a_net_grant_reaches_only_the_resolver_port`. On 7.3.5 `udp_is_refused_without_a_network_grant` now sees Landlock's `Permission denied` before the empty namespace's `Network is unreachable`, and the test accepts the message for its kernel. Linux 6.17: Clippy clean, 16 of 16. Mutants caught: UDP rules as a hard requirement (the sandbox refuses to start on 6.17), no port-53 rule and UDP rights not handled (both on 7.3.5). CI's runners have kernels below 7.2, so CI covers only the below-v10 path. Also re-run: listener mutant S2 (no rule for the `listen` grant), caught on 6.17.

- **No UDP from a program without a network grant (F2; CWE-923, 668; owner decision, 2026-11-02).** `corten-sandbox` runs such a program in a new, empty network namespace inside a new user namespace (user and group IDs mapped to themselves where the kernel allows it; on Ubuntu 24.04, whose AppArmor policy grants no privilege there, they show as 65534 inside), so it cannot send anything, UDP included; Landlock filters TCP only. - **New `corten-manifest` tool (principle 10; owner decisions, 2026-11-02).** `keygen --id ID --out FILE` writes an Ed25519 key file (mode 0600, never overwritten) and prints the `--trusted-key` argument. `sign` writes the header in front of a grants file: `serial` is the Unix time (refused if not above `--previous`), `not-after` defaults to 90 days (at most 366), and `program sha256` comes from the build's provenance (`--provenance`, `--subject`) or the file (`--program`).
