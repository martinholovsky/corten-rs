- **Strategy 8, DirCap extensions (owner decisions, 2026-11-02; CWE-276, 732, 62, 65, 434, 646).** `OpenMode::CreateExclusive` takes a `FileMode` (`OwnerOnly` 0600, `OwnerWriteGroupRead` 0640, `ReadableByAll` 0644): no default, nothing executable or world-writable, and the mode is set exactly whatever the `umask`. New `OpenMode::ReadSingleLink` and `AppendSingleLink` refuse a file with more than one hard link (`FsError::HardLink`), checked on the open descriptor. New `DirCap::store_upload(content, DeclaredType, FileMode)` stores under a generated `upload-` name, never the client's, and records the server-declared type in `NAME.type`. Breaking: `CreateExclusive` callers name a mode.
- **No UDP from a program without a network grant (F2; CWE-923, 668; owner decision, 2026-11-02).** `corten-sandbox` runs such a program in a new, empty network namespace inside a new user namespace (user and group IDs mapped to themselves where the kernel allows it; on Ubuntu 24.04, whose AppArmor policy grants no privilege there, they show as 65534 inside), so it cannot send anything, UDP included; Landlock filters TCP only. If the kernel refuses the namespaces, the sandbox stops unless `--allow-udp-without-netns` is given, which warns on every start. A program with a `net` grant keeps the host's network. This also covers `cargo corten check` and `build`, whose sandboxed passes have no network grant.
- **Manifest format 3 binds grants to one binary (F4; CWE-494, 347; owner decision, 2026-11-02).** A fifth required line, `program sha256 HEX`, names the program the grants are for. `corten-sandbox` opens the program, hashes that open file, refuses a mismatch before the serial state is advanced, and executes the same file through `/proc/self/fd` (programs over 1 GiB are refused). Format 2 is refused. `VerifiedManifest` gains `program_sha256`.
- **New `corten-manifest` tool (principle 10; owner decisions, 2026-11-02).** `keygen --id ID --out FILE` writes an Ed25519 key file (mode 0600, never overwritten) and prints the `--trusted-key` argument. `sign` writes the header in front of a grants file: `serial` is the Unix time (refused if not above `--previous`), `not-after` defaults to 90 days (at most 366), and `program sha256` comes from the build's provenance (`--provenance`, `--subject`) or the file (`--program`). It refuses a key file that is a symlink, reachable by group or others, or owned by another user, and verifies its output before writing.
- SHA-256 moved from `cargo-corten/src/sha256.rs` to the new dependency-free crate `corten-sha256`, used by the checker and the launcher.
- **Key rotation in `corten_std::crypto` (F3; CWE-324, 916, 347; owner decision, 2026-11-02).** Sealed messages are format 2: a version byte and a caller-chosen `KeyId` (32-bit) in front of the nonce, authenticated with the associated data. Format 1 is refused. `AeadKey::generate` and `from_secret` take a `KeyId`. New `KeyRing`: seals with its current key, opens with the key a message names, says when a message should be sealed again (`Opened::reseal`), and retires old keys; duplicate identifiers are refused. `password::verify` returns `Check::Current` or `Check::Rehash` (a hash that meets the floor at other costs). `verify_signed` takes the signer's `KeyId` and a `VerifyingKeys` set, and tries only the named key. Breaking: every caller of these four changes; nothing is released.
